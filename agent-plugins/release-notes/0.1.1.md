# Nacos AI Registry Agent Plugins 0.1.1

Release notes for the Codex and Qoder adapters. Source versions are aligned at 0.1.1;
published packages are available only when attached to a corresponding
[GitHub Release](https://github.com/nacos-group/nacos-plugin/releases).

## Fixes

- Fix false Skill upload conflicts after the plugin or another client reads a ZIP.
  Download counts and update timestamps no longer invalidate an unchanged plan.
  Local/remote content, visibility, version selection and review state remain protected.
- Record and recheck the selected version's content hashes for submit/publish plans,
  then recheck governance metadata before writing.
- Apply the fix independently to both adapters, with 10 new conflict regression tests each.

## Upgrade from 0.1.0

- Upgrade through the original installation source and retain existing configuration,
  credentials, installed Skills and connections. Follow the host's reload instructions
  when it continues to use an older plugin or Skill.
- Existing upload plans still undergo content and governance checks after normalization.
  Expired or changed-context plans must still be recreated.
- Recreate pending submit/publish plans made by 0.1.0: they lack the content baseline
  required by 0.1.1. Unknown write outcomes must be reconciled before retrying.
- The release adds no new authentication providers, operating-system support or
  automatic resource-update policy.

## Verification and CI

The automated suites contain 118 Codex Python tests, 33 Codex Node tests and 181 Qoder
Python tests. Each adapter also has 13 real Nacos integration tests, run with native
authentication enabled and disabled: 52 integration cases in total.

Integration coverage includes authentication, search/pagination, Skill production and
consumption, review/publish, update/recovery, conflict protection, reuse policy,
uncertain-write reconciliation and MCP/A2A discovery and calls. Nacos is built from
the pinned public commit `1511b5a85f744acb0ad54e8213b1f4d82674799c` (3.3.0-RC).
Downstream HTTP services and the external review scanner are deterministic fixtures.

Five plugin CI jobs retain the full coverage: four Ubuntu/macOS × Python 3.11/3.13
environments verify both adapters, and one job builds Nacos once and runs all four
adapter/authentication combinations. Pure plugin changes no longer trigger Java CI.

See the [integration instructions](https://github.com/nacos-group/nacos-plugin/blob/develop/agent-plugins/integration/README.md)
and the [local acceptance checklist](https://github.com/nacos-group/nacos-plugin/blob/develop/agent-plugins/specs/0.1.1-local-acceptance.md).
Actual host UI, credential permission/restart behavior, native loading, model interactions
and configured upgrade/uninstall still require the recorded host-specific acceptance.

## Compatibility

- Python 3.11+ and a local host executor are required.
- Native credential entry uses macOS Keychain. Linux supports core execution with
  environment-based or no authentication; desktop integration remains unverified.
- Native Windows is unsupported. No new Windows or Linux credential backend is included.
- Qoder remains a conversation/tool workflow without a resource-center page.
- Same-session native Skill/MCP loading depends on host capabilities and is not guaranteed.

# 凭据输入、存储与生命周期规范

本文细化[接入与治理](connection-governance-spec.md)中的凭据边界，供所有 Agent 适配复用。
定义通用行为、可选传输方案和系统存储接口，不表示所有应用或操作系统已经实现。
初始化步骤见[初始化规范](onboarding-spec.md)，应用支持状态保留在各自目录。

## 1. 认证方式与凭据来源

认证协议和凭据来源是独立维度。Nacos 支持何种认证取决于目标服务及协议适配；凭据能否
直接填写取决于应用的安全输入通道和实际执行机器的存储能力。

| 认证方式 | 来源 | 展示与持久化 |
| --- | --- | --- |
| 无需认证 | 无 | 无秘密字段，不生成凭据记录。 |
| 用户名与密码 | 安全页面 | 用户名、遮罩密码；说明本机安全存储方式，普通配置只保存不透明引用。 |
| 访问令牌 | 安全页面 | 遮罩 Token；沿用相同的保存、替换与清除流程。 |
| 用户名与密码 | 环境变量 | 只填写用户名和密码变量名。 |
| 访问令牌 | 环境变量 | 只填写 Token 变量名。 |

受保护的输入、传输和存储都可用时才推荐页面填写。不可用时说明原因，由用户选择已支持
的环境变量或稍后继续；不静默降级为明文文件、普通聊天或无需认证。其他认证协议与安全
入口需扩展契约和验收，不因某一实现尚未支持而在通用层永久排除。

## 2. 页面行为与秘密边界

已有凭据只显示已保存状态和存储方式，不读回密码或 Token 填充输入框。提供更换与清除，
说明清除作用的连接及重新认证影响。修改名称、目录等普通字段不要求重新填写秘密。

提交中禁止重复保存。取消、离开、切换认证或提供方式，以及保存失败或结果未知后清空
秘密输入；非敏感草稿可保留。错误详情不包含请求体或底层原始异常。
结果未知时允许放弃草稿并重新读取持久状态，不自动再次提交密码。

秘密明文不得进入模型上下文、普通工具参数记录、工具结果、操作历史、诊断日志、分析事件、
导出文件、发布包或仓库；浏览器不得用 localStorage/sessionStorage 等持久缓存保存秘密。
密码遮罩、隐藏字段或工具仅对页面可见，都不能单独证明传输安全。
工具记录可能保存加密信封时必须如实说明，不能宣称完全没有凭据相关数据经过平台。

本机保存不表示密码永不离开机器：认证时仍需发送到用户确认的 Nacos 目标。正常部署使用
HTTPS；不向重定向后的其他来源携带秘密。页面与本机进程处理明文的边界必须有明确说明。

## 3. 存储接口与隔离

存储适配器至少提供能力检查、保存、按引用读取、删除及可识别的失败结果。能力检查应能
区分不支持、当前不可用及可尝试访问；“存储已支持”或“引用存在”不保证条目一定可读取。
系统授权拒绝、条目缺失等应可诊断，不能显示为空凭据并继续登录。

普通 profile、CLI JSON、状态文件及工具输出仅持有不透明引用与配置状态。读取入口必须
核验引用归属，不能暴露接受任意引用并返回秘密的普通工具。
隔离范围至少覆盖应用/插件的存储空间、连接、身份、目标地址、认证类型和 Client/Admin
用途。同一 Nacos 目标在用户明确选择共用认证时可共用记录；独立管理认证保持独立。

更改目标 URL 时不得自动把旧凭据送往新目标；更换账号使旧权限缓存和计划失效。
Nacos、下游 MCP、远端 Agent 和网关入站凭据分别管理，不能因服务发现而自动传递。
当前页面凭据实现是否覆盖下游服务由各适配声明，不能从 Nacos 登录能力推断。

多个 Agent 可以复用同一套存储实现，默认各自隔离凭据记录。跨应用共享凭据是需要独立
授权、归属和迁移设计的能力，不能通过共用服务名或猜测引用实现隐式共享。

## 4. 保存、替换与清除

| 动作 | 一致性要求 |
| --- | --- |
| 首次保存或替换 | 核对目标与配置修订，先建立新条目，再原子保存引用；成功后清理不再使用的旧条目。 |
| 配置写入失败或结果未知 | 先核对持久配置，保留已被实际引用的条目；仅回滚未引用的新条目，避免破坏一次实际成功的保存。 |
| 清除凭据 | 仅处理选定连接及其归属条目；不误删仍被其他用途引用的条目，配置与清理结果分别核验。 |
| 清理被拒绝 | 登记待清理项并允许重试；明确旧凭据尚未清除，不能报告已完全删除。 |
| 并发修改 | 保存时再次检查上下文/修订，拒绝覆盖另一窗口或会话的新配置。 |

配置和凭据应作为一个一致性操作处理，不能留下“配置成功、凭据缺失”的假成功状态。
替换或清除立即使旧登录缓存失效；日常更新不要求重启应用。关闭重开页面、重开对话、
进程或应用重启后，已保存凭据的可用性需要独立验证，不能只检查引用是否还存在。

卸载插件、清理插件配置及删除本地 Skill 是不同范围。明确清理配置时，核验并清理归属
凭据和相关引用，报告未完成项；保留未获授权删除的本地资源。与[分发规范](distribution-spec.md)
中的安装、升级和卸载语义保持一致。

## 5. 系统存储与能力声明

macOS 的可复用实现要求见[系统钥匙串配置](platforms/macos-credential-store.md)。其他系统
须接入并验证各自安全存储，不能沿用 macOS 结果宣称支持，也不能退回工作区明文文件。
系统存储实现独立于应用页面入口；同一系统上每种应用仍需验证输入、传输、保存和使用闭环。

应用适配记录三个维度：安全输入入口、传输通道、执行机器的凭据存储。任一必需能力未知
或不可用时禁用对应直接填写选项；环境变量分支独立声明。支持状态与实际验收结果见
[初始化与凭据验收](onboarding-acceptance-spec.md)。

## 6. 可选的 MCP 加密信封方案

本节是适用于页面经 MCP 桥接向本机提交秘密的一套可复用方案。采用此方案的实现遵循下述
固定参数；其他已验证的原生安全入口可以采用独立方案，仍须满足第 1–5 节。应用工具名称、
元数据位置及桥接权限由应用适配映射，不把某个应用的专有字段作为通用要求。

1. 页面申请一次性公钥、会话标识和有效期。普通结果仅给就绪状态，公钥等可经应用支持的
   页面元数据交付。每次保存使用新 RSA 2048 密钥，私钥仅保留在本机内存，不导出或持久化；
   会话有效期 60 秒，最多 32 个待用会话。
2. 页面使用 WebCrypto 生成随机内容密钥和 IV，以标准 JWE Compact
   `RSA-OAEP-256` / `A256CBC-HS512` 加密配置与凭据变更。固定算法，不协商降级，不接受
   外部密钥 URL；RSA 包装密钥、AES-CBC 加密、HMAC-SHA512 认证，按标准截取标签。
3. 提交入口只接收密文信封与配置上下文，且仅开放给所支持的页面入口。模型工具参数不收
   秘密明文。平台可能记录密文；私钥留在本机，仅页面及本机插件处理明文。
4. 本机检查格式、长度、固定算法、时效和上下文；RSA 解包后先验证认证标签再解密。
   信封最多 46,000 字符、明文最多 32 KiB。会话单次消费，失败尝试也消费；完成或到期
   释放私钥。保存事务再次检查配置竞争。异常返回固定错误，不回显输入或原始异常。
5. 此方案不依赖页面访问本机 HTTP。浏览器缺少 WebCrypto、工具版本过旧或公钥异常时
   停止提交，不降级为明文 MCP 或聊天补交，不要求用户放宽应用内容安全策略。

加密格式依据 [RFC 7516](https://www.rfc-editor.org/rfc/rfc7516.html) 和
[RFC 7518](https://www.rfc-editor.org/rfc/rfc7518.html)。复用实现仍应验证公开向量、独立实现
互通、篡改、重放、过期、上下文竞争及错误脱敏。禁网浏览器和协议测试不替代目标应用的
真实内嵌页面与系统授权验收。

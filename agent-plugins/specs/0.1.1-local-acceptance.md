# 0.1.1 本地验收操作清单

本清单覆盖真实 Codex/Qoder 应用、系统凭据和模型参与的操作。
自动测试及真实 Nacos HTTP 测试见
[CI 验证说明](https://github.com/nacos-group/nacos-plugin/blob/develop/agent-plugins/integration/README.md)；
功能和版本计划见[roadmap](roadmap.md)。

**两个宿主分别填写结果。** Qoder 无资源中心页面，页面行记“不适用”，不记通过。
新三步向导、Windows 适配、Linux 系统凭据、新宿主及同会话自动加载增强不在本次新增范围内。

- [ ] 使用测试账号、测试命名空间和独立 Skill 目录，资源均为合成样例。
- [ ] 记录 macOS、宿主、模型、Nacos 版本/提交、插件提交和安装包 SHA-256。
- [ ] 准备两版测试 Skill、返回固定结果的 MCP，以及可查询和取消任务的 A2A 服务。
- [ ] 准备带配置、已安装资源和连接的 0.1.0 测试环境，用于升级验证。
- [ ] 密码/Token 走安全输入或测试环境变量；原始地址、截图和操作记录保留在仓库外。

## A. 安装、初始化与目录

| 编号 | 完成 | 操作 | 通过标准 |

| L01 | ☐ | 干净环境安装候选包，打开新会话，查看工具并查询插件状态。 | 插件启动、工具可调用、显示未配置；仅出现在插件列表不算通过。 |

| L04 | ☐ | 跳过首次盘点，再主动打开，只选择一个目录和资源。 | 跳过不影响连接；只扫描选定范围，未选择资源不上传。 |
| L05 | ☐ | 配置不可达地址、错误账号，再纠正并重试。 | 区分连接和认证失败；纠正后恢复，不误报中心没有资源。 |

## D. 模型发现与保存策略

每个隐式用例使用新会话。首轮两端各选一个常用模型，中/英文分别测试，每个
“模型 × 语言 × 场景”重复 3 次，记录所有结果。该抽样不表示覆盖全部模型，
完整 CD-01–34 场景仍按发现规范补齐。

| 编号 | 完成 | 场景 | 通过标准 |
| --- | --- | --- | --- |
| L17 | ☐ | 中心有团队规范 Skill、会话未加载；要求“按团队的 API 规范检查这个示例项目”。 | 不提 Nacos 也能发现适用能力，实际用于检查并完成任务。 |
| L18 | ☐ | 分别发起只有测试 MCP、Agent 能完成的查询。 | 找到正确资源并实际使用；搜索词不带完整业务数据。 |
| L19 | ☐ | 给足代码要求解释；另测“只分析本地文件，不联网”；再测已有适用能力。 | 直接完成或复用已有能力，不重复搜索，不违背来源限制。 |
| L20 | ☐ | 无匹配资源、鉴权失败、用户拒绝保存各测试一次。 | 有界查询并区分原因；继续可完成部分，不重复询问施压。 |
| L21 | ☐ | ask 下成功使用尚未保存的 Skill/MCP，分别保存、拒绝、不回答。 | 先完成任务，再原生询问一次；仅保存选中项，拒绝/未答复不写入。 |
| L22 | ☐ | auto 下成功使用，再切换 never 重复；另测试用失败。 | auto 在允许范围内保存，never 不主动保存，失败试用不作为已验证资源推荐。 |
| L23 | ☐ | never 下明确要求安装；已明确安装后继续任务。 | 明确安装执行；已保存不重复询问，不主动提议移除。 |

映射 DISC03/DISC09、CD-01–34。ask/auto/never 控制发现后的持久复用，不是版本更新策略。

## 记录和完成条件

每个宿主填写一份仓库外记录：

~~~text
宿主 / 模型 / macOS：
Nacos 版本或提交：
插件提交 / 包 SHA-256：
用例编号及重复次数：
操作与实际结果：
结论：通过 / 失败 / 受阻 / 不适用（原因）
脱敏问题描述：
本地证据位置：
~~~

配置保存错误、覆盖用户修改、未授权发布、秘密泄露、主流程无法完成等问题阻止发布。
环境缺失记受阻，不适用须说明原因，二者不算通过。已有宿主能力限制保留降级操作和发布说明。
修复后重测受影响项，无需每次完整重复全部人工操作。

# 本地资源盘点、托管与创建后提示规范

本文约束 F16、F17，定义首次接入已有资源，以及创建或修改资源后的上传提示。
功能分期见 [TODO](TODO.md)，宿主机制与证据见[可行性分析](feasibility-spec.md)。
下述行为是插件设计，不表示安装插件即可获得所有全局事件或自动传输权限。F17 为待评估
的可选能力候选，本文保留其方案；列出的提醒行为仅在决定实施后适用，不构成必交付承诺。

## 1. 触发入口

| 入口 | 行为 | 支持边界 |
| --- | --- | --- |
| 安装后的初始化流程 | 配置 Nacos，盘点本地资源，展示选择与托管策略。 | 使用应用支持的显式初始化入口，不假设安装完成自动执行代码。 |
| 首次打开资源中心或使用插件 | 初始化未完成时提供继续设置入口；用户明确选择目录并发起后才运行盘点。 | 插件须已启动且能访问目标工作环境；页面不是唯一入口。 |
| 插件的 Skill 开发工作流 | 协同 Skill Creator 完成创建/修改和校验，在结束时检查上传候选。 | 只有实际进入此工作流才可承诺调用检查；不改写系统 Skill Creator。 |
| 可选宿主 Hooks | 对支持的文件操作或回合事件检测新增/修改，补充上传提醒。 | 需要宿主和分发渠道支持、Hooks 获得信任；无通用的 Skill 创建完成事件承诺。 |
| 资源刷新或重新扫描 | 比较本地清单与上次基线，补查遗漏的候选项。 | 补查发生时才提示，不能宣称在创建完成瞬间提醒。 |

仅安装一份描述“创建 Skill 后提示上传”的 Skill，不等同于全局注册事件监听。
插件不会自动接管所有 Skill Creator 调用，也不依赖解析聊天历史来判断创建是否完成。

## 2. 首次盘点流程

连接初始化、是否自定义目录及默认值选择见[初始化规范](onboarding-spec.md)。本节从用户
选择盘点开始；提供目录建议、保存目录和执行扫描是不同动作，连接初始化可不进入本流程。

1. 用户进入初始化，选择 Nacos 入口、namespace、身份，以及允许盘点的本地作用域。
2. 适配器读取当前宿主可发现的资源，建立本地清单；此阶段不向 Nacos 传输本地内容。
3. 展示资源名称、类型、来源、位置、可读状态，以及已托管、未托管或不适合导入的原因。
4. 用户按资源选择忽略、仅跟踪、上传草稿或进入发布流程；可批量选择，保留单项结果。
5. 核验目标与内容边界，执行获授权的上传/发布，保存映射及结果；未选择项保持原状。

安装后的 setup、后续打开页面和手动执行初始化共用一份状态，至少记录未开始、待盘点、
待选择、完成和跳过。跳过后仍可正常消费 Nacos 资源，并可在配置或页面重新发起盘点。
状态按宿主环境、身份与作用域保存，避免每次启动重复要求导入；更换项目或身份不能沿用
原来的上传选择。重装插件也不应抹除已有用户选择和映射。

盘点结果可以在配置流程中用结构化列表展示，也可在[资源中心](resource-center-ui-spec.md)
中展示。无页面能力时由对话呈现同一清单及选择结果，不要求先实现 UI 才能导入。

## 3. 盘点范围与来源识别

优先使用目标宿主已验证、允许插件访问的资源列表接口；没有此入口时，对用户授权的
Skill 根目录做有界扫描。宿主暴露给集成客户端的 API 不自动意味着普通 MCP 插件可调用。
目录由适配器按当前版本发现，不能把一种历史路径当作所有应用及版本的唯一目录。

默认目录来源、已有值保留、空候选和无副作用要求统一见
[本机默认值与自定义](onboarding-spec.md#5-本机默认值与自定义)。适配器将实际路径与
用途提供给页面和对话，不能各自维护不一致的默认值。

- 默认范围为当前项目及用户选择的个人 Skill 目录，不递归扫描整台电脑或全部历史项目。
- 初步读取元数据与文件清单；内容打包和完整摘要在选定资源后进行，不执行包内脚本。
- 路径去重同时保留宿主作用域；处理同名 Skill、多个工作区、副本、符号链接越界与不可读项。
- 系统内置、第三方插件缓存中的 Skill 标记来源，默认排除自动上传和自动托管。
  用户明确选择导入有权分发的副本时，也不得改写来源插件的缓存。
- 插件自身的 Skills 和已从 Nacos 下载且未修改的内容不得再次作为“新创建资源”推荐上传。
- MCP 可以盘点连接元数据，但连接配置中的秘密不进入资源包；已有配置也不等于可发布的
  MCP 服务定义。远端 Agent 引用不等于可注册的本地 Agent 执行服务。
- Prompt、AgentSpec 或其他资源只有在存在明确宿主对象与适配契约时才可盘点，不将任意
  Markdown、配置文件或聊天记录猜测成可上传的 agentic 资源。

列表应说明扫描根、成功项、跳过项与失败项。部分目录不可读不应导致整个流程显示为空；
未经扫描的作用域不纳入“已扫描全部资源”的结论。

## 4. 本地托管模型

托管是记录来源、远端映射、内容基线和允许的同步方式，不等于移动或删除原文件。
同一个本地资源可以先仅跟踪，之后再选择远端目标；远端同名资源不能仅凭名称自动认领。

| 对象 | 必须记录的信息 |
| --- | --- |
| LocalResourceCandidate | 宿主环境、作用域、规范化根路径、类型、名称、来源、扫描结果及内容指纹（若已计算）。 |
| ManagementBinding | 本地资源身份、目标 profile/namespace/资源名、上次上传和下载版本/摘要、同步方向、策略。 |
| UploadProposal | 候选内容快照、文件清单、目标、预期副作用、预检结果及草稿基线。 |
| ReminderRecord | 候选身份与摘要、目标、提醒来源、已提示/稍后/忽略状态。 |

这些是插件本地模型。服务端版本和 owner 继续由 Nacos 决定，插件路径名不作为远端 owner。

| 策略 | 行为 |
| --- | --- |
| 不托管 | 保留原资源；不自动同步。可单独选择是否接收以后变化的提示。 |
| 仅跟踪、提示上传 | 记录映射与差异，有变化时提示；内容不自动离开本机。 |
| 本次上传草稿 | 用户选择当前快照与目标，完成预检和草稿写入，不继续 submit 或 publish。 |
| 自动上传草稿 | 仅对明确选择的资源/作用域、目标和内容范围持续生效，检测稳定变化后保存草稿。 |
| 发布 | 单独发起经授权的提交/发布工作流，保留服务端审核与上线语义。 |

“自动上传草稿”不能隐含自动发布；“托管”不能隐含长期、双向、覆盖式同步。
策略可暂停、撤销或更换目标。已有策略覆盖同一操作时不反复询问，目标、文件范围、
可见性或副作用扩大时才需要重新选择。阶段支持哪些策略由 TODO 明确约束。

## 5. 创建或更新后的提示

### 5.1 插件工作流内

插件可以提供“创建并管理 Skill”的工作流，复用宿主可用的 Skill Creator 或用户选定的
创作方式。完成校验后检查最终文件和既有映射，发现未上传的变化时展示以下选择：

- 上传到指定 Nacos，保存草稿。
- 进入提交/发布流程，按服务端结果展示待审核或上线状态。
- 稍后处理，或忽略该资源/该次内容变化。

用户已经要求创建并发布时，直接在授权范围内完成对应流程，不再机械询问同一个问题。
没有配置 Nacos 时保留待处理候选，提供接入入口，不将内容上传到猜测的默认中心。

### 5.2 独立 Skill Creator 与其他工具创建

对用户直接调用 Skill Creator 的场景，可选 Hooks 从本地文件变化建立候选，而不是识别
技能调用名称。它因此也能覆盖支持路径内的手动文件修改，但不能覆盖所有外部编辑器或
宿主工具；本地扫描用于补齐遗漏。

候选需要经过防抖、结构校验和内容摘要核验。一次写入 `SKILL.md` 不代表创作已经完成，
用户中断、文件不完整或持续修改时只保留候选，不立即触发上传。

由各应用适配声明可用的文件操作与回合事件，并验证提醒的触发时机。提醒不得反复
阻止回合结束、阻断工具结果或自动执行上传/发布；超时或提醒失败只记录待处理状态，
不得使 Skill 创建结果丢失。具体事件映射见各应用规范，如 [Codex 可选提醒](../codex/specs/feasibility-spec.md)。

异步 Hooks 完成并不自动唤醒空闲会话。无活动会话时把候选留在资源中心或下次插件交互中，
不得承诺无需宿主能力就能后台弹窗或发起新对话。

### 5.3 去重与环路

提醒以宿主作用域、资源身份、内容摘要与目标为依据。相同变化不在每次文件保存后重复提示；
忽略该次变化与忽略整个资源分别记录。新增内容可重新成为候选，但必须尊重资源级忽略。

下载、回滚、安装、插件升级和插件自身上传产生的文件操作携带操作来源，不能被当作用户
新创作而再次上传。记录上次上传/下载基线，双向都有变化时停止自动动作并展示冲突。

## 6. 上传与发布边界

本地清单确认和服务端预检是两件事。Nacos Skill 上传预检需要接收 ZIP 包，因此虽然
预检不发布资源，包内容仍会传输到 Nacos。用户选定的上传或预检授权必须涵盖明确的目标
及包文件；不能在纯本地盘点时静默调用服务端预检。

上传前重新核验内容快照。文件列表、内容或目标在选择后变化时，更新计划并判断原授权
是否仍然覆盖。处理预检中的草稿已存在、审核中、无权限和版本调整，上传后核验真实版本，
不得强行覆盖他人草稿或把预检推测版本当作上传结果。批量操作保留逐项成功与失败。

自动草稿上传只允许写入已授权目标；出现基线冲突、已有未知草稿、审核中或结果未知时
暂停该项，等待核验或选择。没有服务端 CAS 时仍存在跨客户端竞争，不能承诺无冲突覆盖。

submit 在无匹配 Pipeline 时可能直接上线；“只保存草稿”的动作不得调用 submit。
发布仍遵循[资源管理](resource-management-spec.md)与[接入治理](connection-governance-spec.md)，
不因某文件来自 Skill Creator 或已选择托管而跳过发布权限和服务端审核。

## 7. 验收重点

| 场景 | 验收要求 |
| --- | --- |
| 初始化盘点 | 仅扫描选定范围，本地清单阶段无包内容上行，支持跳过、重开和单项选择。 |
| 新建与修改 | 插件工作流内完成后可提示；Hook 场景独立验证工具覆盖，失败时明确降级。 |
| 部分创建或中断 | 不把不完整内容上传，也不误报为可发布。 |
| 忽略与去重 | 同一内容只提示一次，用户忽略有效，后续变化遵循策略。 |
| 来源和同名资源 | 不自动上传系统/第三方插件；不因同名覆盖已有远端资源。 |
| 预检和草稿 | 传包范围已授权，处理真实版本和草稿冲突；保存草稿不进入 submit。 |
| 反馈环路 | 从 Nacos 下载或回滚不触发重复上传；本地/远端同时变化可见。 |
| 生命周期 | Hook 未信任、插件未启动、页面关闭和重装时不伪报“全局自动提醒已启用”。 |

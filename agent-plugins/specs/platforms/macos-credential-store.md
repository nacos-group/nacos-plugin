# macOS 本机凭据存储实现规范

本文件是[通用凭据规范](../credential-management-spec.md)的 macOS 实现配置，供不同
Agent 适配复用。定义系统能力及实现约束，不代表某个应用已通过验收；当前 Codex 的实现
映射与状态见其[凭据适配](../../codex/specs/credential-onboarding-spec.md)。

## 1. 存储与运行身份

使用系统 Keychain 保存用户名与密码组合或 Token，普通配置只保存随机、不透明引用。
条目不参与系统同步；存储访问由实际执行插件的进程和当前系统会话承担。当前 Python
实现通过 Security.framework 的 SecItem API 读写；系统可能询问 Python 的钥匙串访问权限。
其他运行时可以调用同一系统服务，必须独立验证访问控制与错误行为。

系统用户名是本地上下文，不能充当 Nacos 登录身份。macOS 存储可用也不证明云端进程可以
读取用户电脑的钥匙串；必须核对实际执行机器与进程。

## 2. 引用与所有权

条目按插件状态空间、连接身份、目标地址与用途隔离。应用适配应提供独立的存储空间，
不能因为复用存储类就默认读取其他 Agent 的凭据。引用读取前校验连接绑定及归属，
修改目标地址不能继续使用旧绑定。

引用存在只说明配置曾记录该引用。条目被删除、系统拒绝访问或存储不可用时，返回脱敏的
缺失/拒绝/不可用状态，并说明重试或更换凭据的动作。不得回显底层请求体、秘密或原始异常。

## 3. 保存事务与清理

遵循[凭据生命周期](../credential-management-spec.md#4-保存替换与清除)：先建立新条目，
再原子保存配置引用；失败后核对持久状态并回滚未引用的新条目。替换完成后删除失效旧条目；
遗留引用登记后重试清理。系统拒绝清理时明确显示旧凭据尚未清除。

明确清理插件配置时，仅删除经归属校验的条目；不遍历删除整个钥匙串，不删除本地技能。
升级保留现有凭据与引用，不能通过重新生成连接标识使旧条目失联。

## 4. 加密通道中的本机密钥

采用[可选 MCP 信封方案](../credential-management-spec.md#6-可选的-mcp-加密信封方案)时，
当前 macOS 实现使用 SecKey 内存对象持有临时 RSA 私钥，不导出、不写入 Keychain 或文件。
该临时私钥与持久保存的登录凭据用途不同；具体算法、时效和输入限制以通用信封方案为准。

## 5. 验收记录

分别验证实际 Keychain 保存、读取、替换、清除、权限拒绝与重试、配置写入失败回滚、
新进程读取及应用跨重启使用。测试使用合成秘密；真实配置、运行脚本及轨迹留在仓库外。
每个 Agent 还须验证自己的安全输入入口与本机存储组合；其他应用或其他系统不得继承
Codex 的通过状态。通用场景见[验收规范](../onboarding-acceptance-spec.md)。

# 先完成原任务，再按用户的复用偏好处理

解决普通任务时通过能力发现找到的资源，按 `nacos_status.discovery.installPolicy` 处理，
缺省和旧状态均为 `ask`。不得为了当前任务自行把偏好改为 `auto`；`nacos_configure_discovery`
只在用户明确选择后调用。用户主动要求“去 Nacos 找到并安装/接入/更新/卸载某能力”属于显式管理，
按原有权限、计划与冲突保护处理，不受该偏好拦截。仅提到 Nacos 或要求搜索不是安装授权，
不得把普通任务改标为显式管理来绕过设置。

## 先试用，再决定是否复用

先核对权威资源、确切版本、接口和原任务授权，优先使用当前会话已暴露的能力（`mcp_list` 查实际
工具目录），再考虑免安装试用：

- `nacos_preview_skill` 下载并校验确切版本后读取说明和必要引用，有大小与编码限制，
  不写入技能目录，不自动执行包内脚本。
- `nacos_mcp_trial` 只对已发现的资源身份和权威端点发起调用，不接受任意 URL；工具枚举有分页和
  数量上限。调用前核对可见性、工具目录、schema 和允许的操作。
- `nacos_agent_trial` 按声明且受支持的协议发送任务，外发内容遵循原授权，不保存可复用绑定。
  在途任务句柄绑定原端点，再次发现不迁移目标。

试用不绕过认证、访问拒绝、被禁用的原生工具或宿主安全策略。请求可能已执行但结果未知时返回未知状态，
不盲目重试。操作记录只保留资源身份、必要状态和输入摘要，不保存任务正文、参数明文、凭据或业务响应。

## 判断是否“有效使用”

先交付原任务结果，并如实标注实际走通的路线。有效性由真实任务结果判断：名称匹配、下载成功、
MCP 握手或 `tools/list` 都不构成有效使用。通过 Skill/HTTP 完成不能计作 MCP 已加载或已调用，
也不授权保存尚未使用的 MCP。远端响应里声称“已加载/已执行”的字段不能覆盖本地验证结论。

| 偏好 | 本次选中、确实有用且尚未保存的资源 |
| --- | --- |
| `ask`（缺省） | 询问一次是否保存复用，仅在用户选择后执行。 |
| `auto` | 有效使用后按既有计划流程安装/保存，计划带 `discoveryReuse: "automatic"`，报告实际保存位置与加载状态，不再追问安装意愿。 |
| `never` | 交付结果后结束，不安装也不邀请安装；任务授权内的试用仍然允许。 |

## `ask` 的询问形式

必须实际调用 Qoder 原生 `AskUserQuestion`，不在回答里写出看起来像按钮的选项清单；
只有该工具未暴露或调用明确返回不可用时才退回聊天提问。一次只问一个简短且自包含的问题，
单个 Skill 可用“安装此技能 / 暂不安装”。若 Skill 和 MCP 都有用，允许分别选择、都选或都不选，
不强制捆绑；选项数量受限时拆成多个短问题，不截掉“都不需要”。用用户能理解的名称、用途、
目标位置和待加载步骤说明；MCP/Agent 的“安装”表示保存端点和凭据引用，不下载远程服务，
也不保存注册中心密码。只针对实际选中且有用的资源询问，不罗列整个搜索结果。
未回答、关闭或超时都不是同意；不重复询问用户已拒绝的同一资源。

## 写入与状态保护

用户同意后在 `nacos_install_plan` 或 `nacos_connection_plan` 上传 `discoveryReuse: "confirmed"`，
审阅后 `nacos_apply`。apply 时服务会再次核对当前策略；策略已改变则停止并遵循新选择，
不得为绕过拒绝而去掉该标记。显式管理不带这个标记。`auto` 同样保留文件冲突、目录权限保护和
下游凭据隔离。复用偏好不授予业务写入、远端任务传输、新凭据、发布或覆盖本地修改的权限。

只保存需要复用的最小集合，Skill、MCP、Agent 分别判断；已有匹配的安装或连接不重复写入，
也不自动升级到另一版本。任务受阻或没有有用结果时不安装，也不用安装邀请暗示成功。
已按明确授权保存的资源只说明真实状态，不再问“是否安装”，也不默认提议移除。
偏好改变不追溯清理或迁移已保存资源，也不追认先前未授权的写入。明确移除时使用受保护的
`nacos_uninstall_plan` / `nacos_disconnect_plan`，保留本地修改、无关配置和远端资源。

## 尽量在当前会话完成

Skill、MCP、Agent 都应尽量在用户当前 Qoder 会话完成原任务，不默认要求新建对话，
也不为了获得原生工具而绕过安装策略。

1. 优先复用当前会话已有资源：Skill 可按需读取校验后的内容，Agent 可通过已授权的任务接口使用。
2. 保存技能文件后，请用户在当前对话重新加载 Skills，再确认该 Skill 已出现；写入文件不等于已加载。
   插件不能自行刷新宿主，也不自动重启应用。
3. 保存 MCP 绑定且已获授权时，按 nacos-registry 的步骤用 `query_mcp` + `manage_mcp(action: "add")`
   在当前对话注册原生连接器，该操作需要用户确认。
4. 分别区分：刷新/注册请求已被接受、运行时已连接（`query_mcp`）、当前轮工具目录已暴露
   （`mcp_list`）、业务调用成功。每一级需要对应证据；独立进程或测试会话的成功不能当作当前对话生效。
5. 原生入口不可用或当前轮尚未加载时，可继续用 `nacos_mcp_trial` / `nacos_agent_trial` 的适配路线并
   标明实际路线，不宣称原生已加载。新建会话是最后的兼容步骤，不自动触发，也不重复安装。

# 资源中心页面

`0.1.0-dev.10` 在连接启动时保留页面快照，避免升级移除旧安装包后打开页面导致连接退出；全局与对话入口仍明确区分，保留 Skill 使用主按钮、默认查询、可选关键词和统一控件间距。[逐页对照表](../specs/ui-conformance.md)记录验证边界。页面以已选定的[UI 规范](../specs/resource-center-ui-spec.md)为基线逐页修正。
页面和 CLI/MCP 共用计划、文件基线、受管状态与独立服务认证。旧探针不属于运行依赖。
本地自动测试、浏览器交互和构建包检查已完成；新版实际 Codex 内嵌闭环仍须单独验收，
具体状态见[测试矩阵](../specs/test-matrix.md)。

## 打开入口

安装并启用插件后，可在对话中选择 Nacos AI Registry，要求调用：

- `nacos_open_center`：全局页面，入口名称为 **Nacos AI Registry**。
- `nacos_open_center_panel`：当前对话侧栏，入口名称为 **资源中心**。

使用构建产物默认 marketplace 时，可点击
[打开 Nacos AI Registry](codex://plugins/nacos-ai-registry@local-nacos-registry/app/nacos_open_center)。
自定义 marketplace 需要将链接中的 `local-nacos-registry` 换成自己的 marketplace 名称。
无页面的客户端仍可使用原有对话向导与工具。

`codex://plugins/<plugin-id>/app/<tool-name>` 是全局页面链接，必须指向注册了
`global` 入口的 `nacos_open_center`。不能直接把工具名替换成
`nacos_open_center_panel`：后者只注册 `thread` 入口，应从当前对话侧栏的插件入口打开，
或在对话中调用该工具后展开到侧栏。两个入口复用同一份代码和本地状态，分别加载
带明确入口标识的页面资源，避免依赖可选的应用上下文字段。

在目标对话的资源中心中，进入 **已接入 → Skill 查看详情 → 在当前对话中使用**。
该按钮交接名称、版本、来源和安装位置，不自动证明技能已经被加载。
全局页面或消息能力不可用时显示“复制使用说明”，并说明可从目标对话打开侧栏。
左侧导航或“更多”菜单中的 Nacos AI Registry 属于全局入口；在那里看到复制按钮是预期行为。
实际页面版本与当前对话的 MCP 进程可能不同；核对工具返回的版本和入口类型，
不能仅用已安装版本证明当前会话已重新加载。

若插件可见但页面入口缺失，先区分“已安装”和“当前应用已加载工具”：

1. 确认链接使用当前安装的完整插件 ID，并指向对应的全局入口工具；更换 marketplace
   会改变插件 ID，旧链接不能继续使用。
2. 按 `Cmd+Q`（macOS）完整退出桌面应用，重新启动；只关闭窗口不会保证重新加载。
   回到项目，打开全局入口或上述直接链接。
3. 若旧对话仍未列出页面工具，在同一项目新建对话，选择 Nacos AI Registry，发送
   “调用 nacos_open_center_panel，打开资源中心”。
4. 若新对话也没有工具，检查插件是否启用、Python 是否可执行，以及本地 MCP 启动错误。
   若工具已加载而资源读取或页面桥接失败，保留该具体错误，不能把它误报为安装成功。

更新 marketplace 指向的源码或构建产物后，通过支持的安装/更新流程重新加载，勿编辑安装缓存。
完整重启的要求来自[官方本地插件说明](https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually)。

### 页面提示无法打开

先查看具体错误，区分工具连接、资源读取和页面内操作：

- `Transport closed`：当前对话的 MCP 连接已断开。页面刷新本身不会重建该连接。
  关闭失败的侧栏页，在目标对话中重新调用 `nacos_open_center_panel`。
  若连接已经重建且返回当前版本，就不需要重启；若仍断开，再完整退出并重新打开 Codex。
  展开这次新生成的页面；旧消息中的卡片仍可能引用旧版资源。
- `Page resource not found`：页面卡片引用的资源与当前进程不匹配。
  关闭旧页，重新调用页面工具；不要反复打开旧卡片。
- `Page assets could not be loaded`：安装内容不完整或加载时发生文件错误。
  完整重启后重开；若仍失败，重新安装完整构建包。其他工具不因页面加载错误而退出。
- 页面已经显示、具体操作失败：按页面错误诊断连接、权限或操作状态，不能视为页面入口故障。

如果重启后旧对话仍使用旧工具目录，可在同一项目新建对话验证入口。
只有工具返回版本、入口类型和原生页面资源读取都匹配，才能确认加载了当前版本；
工具返回 `ready` 本身不能证明页面已展示，更不能证明消息已交接。
进程内页面快照保持该进程启动时的版本，升级不会静默替换正在操作的页面。

## 三个主视图与独立子页

| 入口 | 操作 |
| --- | --- |
| 已接入 | Skill、MCP、Agent 共用资源列表，各自提供详情与动作；`⋯` 只打开原行旁浮层。 |
| 发现资源 | 默认分页列出全部可见资源，名称可选，支持类型筛选与分页追加；详情逐步选择目标、核对变更、执行并显示结果。 |
| 我的资源 | 已认证身份拥有的 Skill；已发布、草稿、审核版本可并存，按具体版本提交与发布。 |
| 设置 | 独立子页，隐藏三个主标签；左侧连接与认证/技能目录，右侧摘要或编辑，高级信息默认收起，返回恢复原工作区。 |
| 本地技能 | 主动扫描、默认不选、逐项跟踪/忽略、预览上传，支持跳过和重新进入。 |
| 待处理操作 | 当前上下文内的未知结果核对和有证据的本地恢复；不提供盲目重发。 |

宽屏保留列表和详情，窄屏改为带返回入口的单列详情。卸载或解除接入使用一次确认弹窗；
其他操作在当前详情或上传子页中逐步切换，不把表单、确认和结果并排展示。
菜单支持方向键、Escape 和外部关闭，关闭后恢复焦点。主题与容器变化不重新发送请求。

“我的资源”仅支持原生 Admin login；使用已认证用户名请求 owner 筛选，再核验返回项的 owner。
本地身份标签不作为服务端所有权证据。token 与匿名模式无法可靠确定所有者，显示不支持；
不会用全部可见资源填充该列表。

设置默认只输入一个 Nacos API 地址；独立管理地址/认证按需展开，已有独立配置会保留。
操作范围使用中英文标签；连接检查显示进度、结论和时间，不把读取通过当成写权限。
页底显示实际构建版本。技能盘点从“我的资源 → 本地技能”进入，设置只负责目录配置。

## 操作与状态

页面先读取本地状态；首次进入发现视图时自动读取全部可见资源的第一页。输入关键词或
选择类型后点击搜索筛选；清空关键词可查询全部，后续分页点击加载更多。盘点、发送任务
和上传均由用户显式触发。
上传先展示本地文件清单、目标和内容摘要；点击预检才发送 ZIP。文件变化会阻止使用旧摘要。
安装、上传、发布与解除接入先生成计划，展示实际目标、版本和影响，再执行所选计划。
服务端无审核流程时，提交可能直接上线；保存草稿不会自动提交。

切换中心、namespace、身份引用或操作范围后，旧页面请求与旧计划会被拒绝，需要刷新。
关闭重开从同一份本地状态读取；页面不维护另一份安装记录。结果未知时检查操作记录，
不会自动重试写入或远端任务。当前应用加载及 Skill 的真实使用仍需独立验证。

页面不加载远端脚本，不直接向 Nacos 发请求；所有动作经过本地 MCP 核心与相同权限检查。
远端描述按文本展示。凭据值不进入表单；具体环境设置和操作记录只留在用户本地。

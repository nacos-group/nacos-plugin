# Codex 资源中心 UI 设计

**状态：改版设计基线，尚未实施。** 用户已选择“简洁工作台”：贴近 Codex，突出列表、搜索
和当前操作。本文件承接[通用 UI 规范](../../specs/resource-center-ui-spec.md)，定义 Codex 的
具体布局、样式、组件、工具映射与验收用例；逐项操作以
[通用操作与状态规范](../../specs/resource-center-interaction-spec.md)的 UIX-01–UIX-14 为准。
当前 SVG 版本已选定为设计基线，图册与文字必须保持一致；资源权限和生命周期不在此重定义。

Codex 的数值和控件选择只适用于本适配。其他 Agent 插件复用通用操作，依据各自应用的
字体、主题、组件和容器调整 CSS；不要求使用 Codex 的灰度、尺寸、断点或同一前端框架。

当前 `0.1.0-dev.3` 页面已由用户确认在重启后出现，并完成若干简单操作。该反馈证明入口和
基础使用可用，不等于所有状态、重开一致性和下面的新设计已验收。完整状态见 [TODO](TODO.md)。
本轮只更新规范和设计示意，不改变运行页面、工具协议或已安装包。

## 1. 现状与改版目标

以下问题来自现有 center.html（实现交付时见 `agent-plugins/codex/src/nacos_registry/ui/center.html`） 的结构与交互审阅，
不是对用户尚未逐项报告的问题作推断。

| 当前实现 | 使用上的影响 | 改版要求 |
| --- | --- | --- |
| 每张接入卡片同时展示详情、核验、更新、卸载、使用等按钮 | 主要动作不突出，列表难以扫读 | 统一资源行；一个主要动作，其他进入更多菜单或详情 |
| 配置与盘点同页，所有认证方式字段一起出现 | 低频设置占据大部分空间，新用户难判断必填内容 | 设置与本地技能分开；按认证/用途逐步展示 |
| 详情、确认、结果共用一个无返回层次的区域 | 上一步输入和来源不清楚 | 详情内部步骤栈，返回保留输入；窄屏以子页呈现 |
| 主要按钮叫“生成安装计划”“执行此计划”，结果依赖 JSON | 用户需要理解内部工具才能操作 | 使用业务动词与字段摘要；技术响应默认折叠 |
| 执行后自动切到已安装，导航/关闭也显示“已更新” | 流程打断且反馈不准确 | 更新原列表；成功留在当前区；导航不生成成功提示 |
| 所有动作都进入全局 busy 并设置 app.inert | 点击一个按钮后整页不可用 | 查询局部加载；写操作只锁关联动作，保留浏览 |
| 窄屏把详情移到列表前面，视图重建丢失结果 | 页面跳动，返回需重新定位 | 窄屏单页进退；保存查询、已加载页、选中与滚动位置 |
| 固定蓝色强调、大 Logo 和卡片套卡片 | 与 Codex 的工作区观感不协调 | 继承字体/主题，中性结构，减少边框与装饰 |

本次改版覆盖 Skill 生产消费、MCP/Agent 消费、单中心配置及本地 Skill 盘点。Prompt、AgentSpec、
多中心、在线 Skill 编辑器、MCP/Agent 注册管理、自动同步和完整审计控制台不因此进入本期。

## 2. 两种入口、一套工作区

| 入口 | 工具 | 页面策略 |
| --- | --- | --- |
| 全局页面 | `nacos_open_center` | 全局导航名称 Nacos AI Registry；适合搜索、管理、设置和盘点 |
| 当前对话侧栏 | `nacos_open_center_panel` | 侧栏名称资源中心；同一数据和功能，布局根据容器宽度变化 |

两个工具绑定同一版本化 UI 资源，每个工具只声明自己的入口类型。桥接初始化后读取本地
`nacos_status`，再决定首屏。不得仅因全局入口被点击就把内部默认目录当成用户当前项目。
页面权限、发送消息和显示模式按实际协商结果处理；不承诺所有 Codex 版本都有这些能力。

未初始化时显示“连接 Nacos”欢迎区，三步设置完成后提供“发现资源”和可选“盘点本地技能”。
日常页面顶部为资源中心标题、连接/namespace 摘要、待处理操作和设置；不再显示大号 N 标志。
三项主导航固定为 **已接入 / 发现资源 / 我的资源**。本地技能从我的资源工具栏进入，
设置中的目录分组也可跳转；它们不是第四、第五个主标签。

“在当前对话中使用”只在具有有效对话上下文与消息能力时发送选定引用。全局页面或能力
缺失时显示“复制使用说明”，用可读资源名称、版本与来源，不给用户一段裸 JSON。
剪贴板能力不可用时提供可选中的文本。不能通过工具自行创建对话来规避该限制。

## 3. 布局与尺寸

按 **MCP 页面容器实际宽度**布局，不按桌面窗口尺寸猜测。建议使用 container query 或
等效的容器测量；CSS 必须允许字体缩放和长中文标题换行。

| 容器宽度 | 布局 | 具体约束 |
| --- | --- | --- |
| ≥ 1040 CSS px | 列表与详情并排 | 页面内边距 24；内容最大宽度 1240；间距 24；详情宽 400，列表至少 568；无详情时列表铺满 |
| 640–1039 CSS px | 单工作区 | 内边距 20；详情替换列表并有返回；设置表单最大宽 680 |
| 320–639 CSS px | 紧凑侧栏 | 内边距 16；顶部上下两行；搜索按钮可独占一行；详情/操作均为单列子页 |

断点是初始设计值；字阶或缩放导致最小宽度不满足时，提前退回单列，不挤压文字。
三项导航正常宽度下不横向滚动；空间不足时用带当前名称的可访问视图菜单，不裁掉标签。

每个工作区只保留一个纵向滚动容器。并排时列表与详情可分别滚动，避免外层再叠一层滚动。
操作区在空间足够时贴近详情底部并预留内容空间；高度不足、键盘弹出或缩放时回归正常
文档流，不覆盖字段或结果。不使用 `100vh` 去模拟整个 Codex 窗口。

[宽页面与侧栏示意](assets/resource-center-layout.svg)仅展示目标结构，示例数据不代表真实测试资源。

## 4. 页面规格

### 4.1 已接入

首屏为标题、资源类型筛选与列表，不放技能数/服务数的大号统计卡。可显示本地清单计数，
不得将当前页数量冒充总量。列表字段顺序：类型图标、名称/用途、版本/范围、状态、主要动作。

Skill 显示安装版本和目录摘要；MCP 显示连接状态；Agent 显示接入状态，任务进度在详情中。
更多菜单按类型显示检查、更新和解除接入，危险动作最后排列并分隔。当前未实现更新检测
接口时，用“检查更新”进入解析与差异流程，不在行上虚构“有更新”。

详情中展示完整安装目标或服务地址、来源与最近核验信息。核验记录缺少时间或证据时显示
“未记录”，不能用页面打开时间补齐。安装成功后显示“已安装，待 Codex 加载确认”；
普通文件核验通过只更新文件/访问维度，不把加载状态改为可使用。

### 4.2 发现资源

搜索框与按钮位于列表上方，同一工具栏中显示全部/技能/工具服务/远端 Agent 的类型筛选。
标签筛选有服务端与交互验证后再增加，不为能力列表中的可选字段都生成输入框。
查询期间显示列表区域进度；已有结果保持可读且标明正在刷新。初始状态只提供搜索说明。

每行可直接“安装技能”或“连接工具/Agent”，已接入的同版本资源主要动作改为查看接入。
通过完整引用、实际版本与目标记录判断，不能仅比较名称。未确认最新版本时不宣称无更新。
读取详情失败保留搜索摘要并禁用依赖该读取的写入，提供“重试读取”。

技能安装步骤：

1. 选择合法安装目标和版本。搜索中的确切版本可预选，用户可改为默认版本解析。
2. 点击“查看安装变更”调用安装计划，展示实际版本、完整目标目录和新增/修改/删除数量。
3. 在同一区域点击“安装技能”或“更新技能”，执行已核对计划；按钮立即显示执行中。
4. 展示具体结果与加载说明，更新原行。提供“查看已接入”次要动作，继续搜索不丢失条件。

缺少安装目标时提示“先添加安装目录”，打开设置中的目录分组；返回后重新生成计划。
当前工具不能列所有 Skill 版本，不能画一个虚构的完整版本下拉；先提供“默认版本 / 指定版本”
与明确的解析结果。只有消费端版本枚举接口验证后才替换为完整版本选择器。

### 4.3 我的资源

标题下展示已认证 owner 的可读说明，工具栏提供名称筛选与“本地技能”。列表区展示
已发布版本与正在编辑/审核版本，两者并存。若认证方式无法确认 owner，显示限制和
“配置管理身份”动作，不显示零项或让用户自行输入 owner 过滤。

资源详情包含说明、可见性、版本列表；选择版本后展示审核摘要及允许的动作。
“提交版本”确认区明确“有审核流程时进入审核，无匹配流程时可能直接发布”。只有核心
允许普通发布时提供“发布版本”；不新增跳过审核、强制发布或远端删除能力。
没有开发权限时保持当前页面的解释与返回发现资源入口，不能自动切换管理员身份。

### 4.4 本地技能

独立子页，顶部显示步骤与返回来源的入口；从我的资源进入时显示“返回我的资源”，
从设置或初始化进入时保留该来源。先列已配置目录及“添加目录”，点击“扫描所选目录”
才开始扫描。扫描后显示列表，未选项保持原状；不可读资源保留行并说明原因。
批量选择首期只提供跟踪/忽略；上传按单项进入，未实现批量上传前不展示“全部上传”。

上传按“文件与目标 → 发送并预检 → 核对草稿变化 → 保存草稿 → 结果”呈现。
文件清单显示路径/大小和总量。预检可能传输文件，按钮旁用一句话说明，不作为隐藏说明。
初始不显示已勾选的同名绑定/覆盖开关；冲突时展示目标及原草稿信息，用户选择后再预检。
只知道冲突文字而没有结构化依据时，先补充核心返回或只读核验，不能猜测要覆盖的对象。

跟踪/忽略后更新该行并展示逐项结果；草稿上传成功保留扫描列表位置，提供查看远端资源。
跳过初始化不能将已有跟踪结果清空；重新扫描使旧候选选择和上传摘要失效。

### 4.5 设置

进入设置后使用独立子页布局：隐藏“已接入 / 发现资源 / 我的资源”三个主标签及日常
工具入口，顶部只显示“返回资源中心”、设置标题和连接摘要；宽屏使用设置分组导航，
窄侧栏将分组置于内容上方。摘要、编辑、保存完成与检查失败均使用这一布局。
返回恢复发起位置的主视图、筛选、详情及滚动；设置内部切换状态不重置来源。
取消编辑回到设置摘要；离开未保存表单保留输入或明确提示，不能静默丢弃。
配置变更导致身份、namespace 或作用域变化时，返回只保留可靠的视图意图并重新读取；
旧范围的数据、选择和计划不恢复。具体转换见通用 UIX-12。

设置主页显示连接摘要和“编辑连接”，下设身份、目录、操作范围、高级四组。
首建使用三步表单；已有连接修改时沿用原标识，不因改展示名称更换 id。
消费读取作为基础用途；开发/发布与服务调用按需选择，默认不全选。

认证类型与字段规则：无需认证不展示凭据字段；原生登录只显示用户名/密码变量名；token
只显示 token 变量名。管理认证只在启用开发用途或用户主动配置时展开，Client/Admin
保持独立。技术变量名只能引用环境值，不在页面填写实际密码。

“保存配置”和“检查连接”是两项动作。字段错误内联显示，提交失败保留输入。地址、
namespace、操作范围发生变化后使旧计划失效；保存成功返回设置摘要，可继续原工作流。
目录用可添加/移除的行，每行标明用途与完整路径，不要求编辑多行文本协议。标识自动生成、
项目目录别名和文件选择器均需具体适配支持，现阶段没有支持则提供清晰的手动输入。

### 4.6 待处理操作与 Agent 任务

当前 `status` 只提供未完成/未知操作，不支持完整历史分页，因此顶部入口先叫“待处理操作”。
展开按时间与资源列出当前上下文的操作；完成后可在当前结果区查看，不能承诺长期完整历史。
与当前上下文不匹配的旧记录不得混入主列表，需核心补充可靠过滤或在隔离的历史入口中处理。

Agent 发起任务使用明确的文本输入与接收目标。结果分为回复文本、任务状态及相关操作；
多模态/结构化内容无专用展示时给出受限说明和脱敏详情，不丢弃错误或假装完整支持。
只对已取得有效 taskHandle 的任务提供查询和取消。取消不撤销已经产生的远端效果。
已知任务的重开恢复需要核心返回可查询任务摘要；现有数据未提供时不宣称已具备任务历史。

### 4.7 类型专属详情与更多菜单

三类资源复用工作区和资源行，详情内部有专属分区：Skill 展示文件、来源与更新变更；
MCP 使用概览/工具/连接；Agent 使用概览/发起任务/当前任务。我的资源中的 Skill 使用
维护者概览/版本与发布，不与已接入的安装/卸载详情混用。这些分区不新增主导航。

MCP 工具分区展示成功诊断所得的工具描述和输入摘要，区分尚未读取、读取失败与真实空结果。
连接区核对注册信息中的端点、独立凭据引用和完整配置目标；不提供任意端点覆盖。保存、
连接诊断、Codex 加载确认和真实业务调用各有独立状态，不合并为一个成功标记。

Agent 接入只保存服务绑定；发起任务前同时显示接收目标与文本。当前任务分区区分直接
消息、带引用的任务及结果未知；有有效引用才允许查询/请求取消。详情没有任务摘要时说明
限制，不虚构完整任务列表。解除接入使用确认弹窗；请求取消在当前任务区执行后进入等待
远端确认状态，不另套解除接入弹窗，也不把请求已发送显示成已取消。两项动作不自动串联。

`⋯` 按视图和类型生成：已接入 Skill 提供检查、更新、卸载，MCP 提供工具、诊断、连接设置、
解除，Agent 提供能力、任务、绑定设置、解除；我的资源只提供维护入口。选择确切版本后才
提供提交/发布动作。菜单的点击、禁用条件及后续状态见
[通用 UIX-02 菜单规则](../../specs/resource-center-interaction-spec.md#3-uix-02-行内更多菜单)；
[图册映射](ui-storyboard.md#7-通用操作与图稿映射)用于核对具体画面，不另建第二套动作规则。

### 4.8 浮层与步骤的具体形式

`⋯` 打开宽约 240–280 px 的行内浮层，按容器边缘调整展开方向；同时只打开一个。
触发菜单不切换资源行选择，不修改详情内容，也不导航到“更多操作”页面。

更新从 Skill 菜单的检查更新进入右侧变更确认；只有检测到本地修改才显示冲突步骤。
卸载从同一菜单的卸载技能进入独立确认弹窗，两条流程不会同时出现。MCP/Agent 解除
接入使用同一种确认形式，但各自说明本地配置、绑定与活动任务的影响。

确认弹窗建议宽 480–560 px、最大宽度为容器宽减 32 px；背景保留并阻止交互。具有取消
和一个明确的最终动作，默认焦点不落在危险按钮。未执行时允许 Escape 关闭，执行中按
当前操作状态处理关闭与重复提交；成功关闭弹窗，在原工作区显示结果，恢复合适焦点。

Agent 接入与 MCP 连接配置使用详情步骤，成功后在同一区域显示结果与下一步。我的资源
的维护菜单仍是行内浮层；权限不足说明位于选定版本的操作区，不与菜单组成独立面板。
窄屏把详情步骤映射为单列子页，沿用同一返回栈；不把多个步骤缩成小卡片。

## 5. 视觉规则与设计变量

### 5.1 Codex 主题映射

优先采用 Codex 提供的系统字体与语义颜色，缺少主题变量时才使用下表后备值。原生变量只在
主题适配层映射，不分散在组件中；浅色和深色均使用同一层级，不通过透明度降低正文可读性。
实际可用变量和主题通知必须在当前页面桥接中验证，本文不假定存在某个未验证的变量名。
原生主题明确指定浅/深色时优先使用该值；缺少信号时才使用经过记录的后备方案。

控件读取通用的表面、文字、主动作、状态、焦点和密度角色；只有 Codex 主题适配负责
把这些角色转为具体值。应用主题或容器改变时保持当前步骤、草稿、计划和返回来源，
不因重绘重新执行工具。具体值调整必须同时检查两种主题的可读性，不能直接复刻 SVG 色值
而忽略应用实际主题。图稿中的浅/深色只是本适配的后备参考。

### 5.2 本适配的后备尺寸与颜色

| 项目 | 规范 |
| --- | --- |
| 字体 | 应用字体变量；后备为系统 sans-serif；不用下载字体 |
| 字阶/行高 | 页面标题 20/28，分区标题 16/24，正文/按钮 14/20，辅助信息 12/18；字重 400/600 |
| 间距 | 4、8、12、16、24、32 px；同层级保持一致 |
| 列表 | 标准行至少 76 px，内容增加时自然增高；细分隔线，选中行轻背景 |
| 输入/按钮 | 标准高度 36 px；窄侧栏触达区域至少 44 px；长文案允许自然换行 |
| 图标 | 16 或 20 px 单色线性图标，统一 1.5 px 线宽；不使用 Emoji 作为资源状态 |
| 圆角 | 输入和按钮 6 px，独立面板 10 px；优先使用应用提供的对应变量 |
| 边界/阴影 | 1 px 轻边界；列表行不套独立厚卡片；阴影仅用于悬浮菜单 |
| 过渡 | 100–160 ms 的颜色/显隐变化，不做位移装饰；尊重减少动态效果设置 |

| 语义变量 | 浅色后备 | 深色后备 |
| --- | --- | --- |
| 页面/主要表面 | `#FFFFFF` | `#181818` |
| 次级/选中表面 | `#F5F5F5` | `#252525` |
| 主文字 | `#171717` | `#F2F2F2` |
| 辅助文字 | `#626262` | `#B4B4B4` |
| 分隔线 | `#E5E5E5` | `#3A3A3A` |
| 需辨认的控件边界 | `#858585` | `#7A7A7A` |
| 主按钮背景/文字 | `#171717` / `#FFFFFF` | `#F2F2F2` / `#181818` |
| 链接与焦点 | `#245EDB` | `#9DBBFF` |
| 成功文字/背景 | `#166534` / `#F0FDF4` | `#86EFAC` / `#10281B` |
| 注意文字/背景 | `#92400E` / `#FFF7ED` | `#FCD34D` / `#302312` |

分隔线用于组织内容，不承担控件可见性；按钮边界、焦点和文字按通用规范做实际对比度检查。
一处操作区最多一个实心主按钮。列表多行可以各有轻量动作，但打开确认步骤后视觉焦点
只落在当前确认动作。更新/检查为中性按钮，卸载/解除使用危险文案，避免整页红色。

该视觉方向参考[官方 UI 指南](https://developers.openai.com/plugins/concepts/ui-guidelines)的
系统字体、语义颜色与清晰层级原则。以上数值为本项目设计选择，不是 OpenAI 强制规格。
入口机制参考[Extensions 文档](https://developers.openai.com/plugins/build/extensions)，支持范围以实测为准。

## 6. 组件与状态

| 组件 | 必须具备的状态/行为 |
| --- | --- |
| 工作区框架 | 未配置、初始化中、正常、桥接断开；稳定保留上下文与导航 |
| 资源列表/行 | 首次加载、刷新、空结果、失败、选中、权限不足；区分资源引用与安装记录身份 |
| 详情工作区 | 读取、显示、编辑、确认、执行、结果；返回栈与焦点恢复 |
| 操作摘要 | 动作、资源、版本、来源、目标、文件变化、可见性；未知字段明确标注，技术详情折叠 |
| 配置字段 | 默认、编辑、校验错误、禁用原因；动态必填与未保存草稿 |
| 状态反馈 | 字段/行/页面三级；成功不抢焦点，冲突与未知结果持续可见 |
| 版本列表 | 同时展示 online/draft/reviewing/reviewed；选择后决定动作 |
| 批量操作条 | 无选择时隐藏；有选择显示数量和合法动作；逐项结果不被一个 toast 替代 |

状态文案分维度映射，不将不同协议的状态合并成一个“成功”：

| 事实 | 用户文案与限制 |
| --- | --- |
| `pending_host_verification` | 已安装，待 Codex 加载确认；不是未安装，也不是已验证可使用 |
| `pending_host_reload` | 连接配置已保存，待 Codex 刷新；展示下一步说明 |
| `configured_unverified` | 已接入，尚未检查连接 |
| 文件/远端读取验证通过 | 文件与访问检查通过；不改写应用加载证据 |
| `completed` 操作 | 按 action 翻译为已安装/草稿已保存/已发布等；Agent 任务 completed 只表示任务协议状态 |
| `result_unknown` | 已发送，结果待核对；保留操作记录入口 |
| `recovery_required` | 需要恢复本地状态；说明恢复范围，不承诺回滚远端发布 |
| `reviewed` | 审核已完成；检查结论另行展示，不等同已批准 |

## 7. 工具映射与已知缺口

本表用于后续实现，不把新增交互直接等同于已有后端能力。工具名只出现在开发规范，
不要求用户在页面中选择工具名或填写 JSON。

| 页面行为 | 现有工具 | 限制与改版要求 |
| --- | --- | --- |
| 启动/上下文 | `status` | 只证明本地状态；当前历史/安装记录过滤粒度需按身份、来源和作用域复核 |
| 保存/检查连接 | `configure`、`diagnose` | diagnose 只读 Client；没有独立 Admin 写权限探测，不显示写权限已验证 |
| 发现 | `search` | 保留 cursor；前端维护已加载页与请求序号，不能伪造总数 |
| 我的资源/版本 | `my_skills`、`skill_status` | 原生 Admin login、owner 核验；技能版本详情不用于给普通消费者开放管理面 |
| 安装/更新/卸载 | `install_plan`、`uninstall_plan`、`apply` | 摘要消费计划字段；版本选择变化必须重新规划；没有消费端版本列表和独立更新摘要工具 |
| 服务接入 | `discover`、`connection_plan`、`apply`、`mcp_probe` | Nacos 与下游凭据独立；工具发现不等于 Codex 实际调用 |
| 服务解除接入 | `disconnect_plan`、`apply` | 只移除受管本地连接；MCP 展示刷新要求，Agent 的取消任务另行处理 |
| 本地技能 | `scan`、`select`、`onboarding` | 跟踪/忽略有逐项结果；上传单项处理，无扫描自动执行 |
| 上传 | `upload_preview`、`upload_plan`、`apply` | 传 contentHash；同名/草稿冲突需要补齐可读结构化信息，不能解析英文错误字符串决定覆盖 |
| 提交/发布 | `publish_plan`、`apply`、`skill_status` | submit 可能直接上线；预览展示实际 scope 和确切版本 |
| Agent 任务 | `agent_send`、`agent_task` | 有 taskHandle 才能查询/取消；重开任务清单需补充受上下文限制的摘要读取 |
| 处理异常 | `inspect_operation`、`reconcile`、`recover` | 不提供通用远端回滚；操作历史/上下文过滤不足时先限制界面范围 |

工具调用均使用 `nacos_` 前缀。所有页面请求带最新 `_context`，核心仍检查真实权限及计划
基线；前端禁用按钮不能替代后端校验。只读请求用“上下文 + 视图 + 请求序号”隔离，
写入以 planId/operationId 跟踪；出现超时先读记录，不能在前端自动重新发送写请求。

当前 stdio MCP 与状态锁串行执行；UI 可以保留浏览和编辑，但不能承诺多请求并发执行。
改版至少避免把关闭详情、切换已有列表、复制说明也排进执行锁。配置在执行中的写操作
结束前不得切换，原因直接显示；完成后再进行上下文失效处理。

页面展示状态保存在当前页面内存或应用允许的会话状态中。默认不把查询、私有内容和任务
正文持久写入浏览器存储；完整重开恢复的事实来自核心，视图恢复没有能力时回到可靠默认页。

## 8. 实现组织与兼容约束

改版按职责拆分主题/组件、页面视图、请求与状态、动作流程。是否引入前端框架不由视觉
规范决定；运行产物仍打包在插件中，无外部 CDN、外部字体或安装时前端联网依赖。
允许源码模块化后构建为单个 HTML；不再把所有状态与视图混在难以维护的全局函数中。

通用操作负责步骤、可用动作和返回约束；Codex 能力适配负责第 7 节工具映射、页面桥接、
对话交接和加载确认；Codex 视觉适配负责 CSS 与布局。动作逻辑不直接引用颜色、像素
或主题变量。当前先明确逻辑边界，不在只有一个实现时强制创建共享前端包。
后续提取共用逻辑时，菜单、计划失效和未知结果处理仍来自 UIX 契约，各应用分别提供样式。

保留既有状态 schema、安装目录、资源归属和工具语义；若为任务摘要/结构化冲突增加只读
字段，应向后兼容并做针对性验证。主导航改名不迁移或改写用户资源数据。
深色主题变化、页面重连和容器宽度变化不会重提写入；旧版本页面的计划仍按核心基线拒绝。

## 9. 改版验收与实施拆分

自动化检查针对状态转换、上下文隔离、重复提交、计划失效和协议字段；不写只镜像 DOM
实现的测试。视觉验收与真实 Codex 流程单列，单元测试数量不能代替观感及实际可用性。

| 用例 | 验收内容 |
| --- | --- |
| CUI-01 消费首次接入 | 仅填写消费所需信息可保存；检查连接结果准确；可跳过本地盘点 |
| CUI-02 搜索与返回 | 搜索、加载更多、开详情、返回后查询/列表/滚动仍在；更多菜单不切换详情，关闭归还焦点；没有重复远端写入 |
| CUI-03 安装与更新 | 目标/确切版本/差异可读；当前只呈现一个步骤；更新冲突按条件出现，卸载/解除一次确认；执行一次，结果原位反馈 |
| CUI-04 我的资源 | owner 正确；草稿和发布版本并存；无权限/未知身份/空列表明确区分 |
| CUI-05 上传与冲突 | 先看文件再传包；内容变化、同名绑定和草稿覆盖都有明确处理路径 |
| CUI-06 MCP 与 Agent | 接入配置、连接核验、Codex 加载、实际调用分别显示；任务结果可读，未知结果不重发 |
| CUI-07 中断和并发 | 双击不重复写入；可浏览已有内容；页面重开/对话修改/身份变化使旧计划失效 |
| CUI-08 失败反馈 | 断网、拒绝、审核失败、部分成功、超时都保留输入与可操作下一步 |
| CUI-09 视觉与可访问性 | 320/390/768/1024/1280 宽、浅深色、200% 缩放、键盘、长中文名称/路径，无遮挡与横向溢出 |
| CUI-10 入口与闭环 | 全局页和会话侧栏分别真实打开；搜索→接入→关闭重开可核对同一资源与状态 |
| CUI-11 设置与返回 | 四种设置状态均无三主标签；取消编辑回摘要；编辑/保存/检查不覆盖来源；上下文变化后重新读取而不恢复旧数据 |
| CUI-12 主题与流程独立 | 在菜单、表单、确认与执行状态切换主题/容器，样式随应用变化，步骤、输入和返回来源不丢失，不增加写请求 |

这些用例同时验证 [UIX 操作契约](../../specs/resource-center-interaction-spec.md)；
图稿与用例的对应关系见[图册映射表](ui-storyboard.md#7-通用操作与图稿映射)。
尚无实际界面或工具支持的 UIX 分支必须标为待实现/受限，不能因 SVG 可点击而标为通过。

建议顺序：先完成框架/主题/列表与详情，再完成消费流程与局部状态，再处理我的资源、
本地技能和设置，最后补齐核心只读缺口与恢复体验，并执行上述验收。具体待办放在
[Codex TODO 的 UI 改版部分](TODO.md#11-ui-改版待办)，本文落地不等于勾选实现完成。

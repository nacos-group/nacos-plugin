# Codex 资源中心 UI 设计

本文件定义 Codex 的页面入口、布局、主题、组件选择、工具映射和验收映射。
通用信息架构与操作规则由[通用 UI 规范](../../specs/resource-center-ui-spec.md)及
[UIX-01–UIX-14](../../specs/resource-center-interaction-spec.md)统一维护；
初始化、默认值和凭据行为分别见[初始化](../../specs/onboarding-spec.md)与
[凭据管理](../../specs/credential-management-spec.md)。

用户已选择“简洁工作台”：贴近 Codex，突出列表、搜索和当前操作。SVG 是本适配的设计基线，
实际实现及未通过项见 [TODO](TODO.md)、[测试矩阵](test-matrix.md)和[逐页对照](ui-conformance.md)。
规范整理不改变原有验收结论；其他应用根据自己的能力和风格实现通用操作。

## 1. 当前适配范围

本版包括 Skill 生产消费、MCP/Agent 消费、单中心配置与本地 Skill 盘点。
Prompt、AgentSpec、多中心、在线 Skill 编辑器、MCP/Agent 注册管理、自动同步和完整审计
控制台不在当前 Codex 页面范围。页面代码位于 `src/nacos_registry/ui/`。

## 2. 两种入口、一套工作区

| 入口 | 工具 | Codex 呈现 |
| --- | --- | --- |
| 全局页面 | `nacos_open_center` | 全局导航名称 Nacos AI Registry。 |
| 当前对话侧栏 | `nacos_open_center_panel` | 侧栏名称资源中心；布局按容器宽度变化。 |

两入口复用页面代码和本地状态，分别绑定带 global/thread 标识的版本化 UI 资源，避免缓存
混用。工具只声明自己的入口类型；桥接初始化后调用 `nacos_status`，按通用默认入口规则选首屏。
设置侧栏的路由和预填映射见[凭据适配](credential-onboarding-spec.md)。

对话交接遵循 UIX-13。Codex 以工具绑定的资源入口标识和 `hostCapabilities.message.text`
判断发送能力；`hostContext.toolInfo`、`conversationId/threadId` 可能缺失，不作为必要条件。
`displayMode` 不单独证明会话上下文，侧栏展开或全屏不改变原入口性质。
已知 global 或无会话证据的未知入口采用复制说明；对话侧栏具有消息能力时提供发送。
当前三项主导航为已接入 / 发现资源 / 我的资源，设置与本地技能使用通用独立子页结构。

## 3. 布局与尺寸

按 MCP 页面容器宽度布局，采用 container query 或等效测量。

| 容器宽度 | Codex 布局参数 |
| --- | --- |
| ≥ 1040 CSS px | 列表/详情并排；内边距 24，最大宽度 1240，间距 24，详情宽 400，列表至少 568。 |
| 640–1039 CSS px | 单工作区；内边距 20，详情替换列表，设置表单最大宽 680。 |
| 320–639 CSS px | 紧凑侧栏；内边距 16，顶部上下两行，搜索框独占一行，类型与搜索按钮放下一行。 |

字阶或缩放使最小宽度不满足时提前使用单列。空间不足时三项导航改为显示当前名称的视图菜单。
并排列表和详情分别滚动，避免外层再叠滚动；操作区高度不足时回到文档流。
不使用 `100vh` 模拟整个 Codex 窗口。

[布局示意](assets/resource-center-layout.svg)与[图册](assets/ui/index.html)展示 Codex 的具体画面；
单状态、返回、焦点和确认规则以 UIX 契约为准，场景编号不作为产品路由。

## 4. 页面规格

本节只给出通用页面在 Codex 的呈现与当前能力限制。步骤、副作用、返回和异常不另行定义，
对应关系见[图册映射](ui-storyboard.md#7-通用操作与图稿映射)。

### 4.1 已接入

使用类型筛选、资源行和按需详情，不放大号统计卡；字段顺序为类型图标、名称/用途、
版本/范围、状态、主要动作。安装文件与加载分别按第 6 节显示 Codex 文案。
当前没有自动更新检测结果，菜单使用“检查更新”。

### 4.2 发现资源

工具栏包含名称搜索、全部/技能/工具服务/远端 Agent 筛选与搜索按钮。
空关键词、首屏读取、分页和迟到响应遵循 UIX-01/UIX-03；
加载更多放在独立操作区，与末行分割线至少相隔 20 CSS px。

当前消费工具不能列出全部 Skill 版本，选择器使用“默认版本 / 指定版本”并展示解析值；
标签筛选待接口及交互验证后增加。缺少安装目标时，设置跳转定位到“技能目录”。
其余安装与更新流程直接复用 UIX-03/UIX-04。

### 4.3 我的资源

名称筛选采用横向工具栏，“本地技能”位于工具栏。当前仅维护 Skill，
owner 识别依赖原生 Admin login；无法确认时显示限制及“配置管理身份”入口。
维护详情使用概览/版本与发布分区，发布动作映射到第 7 节工具，状态遵循 UIX-09。

### 4.4 本地技能

Codex 独立子页顶部显示步骤及来源返回。目录数量和扫描结果摘要使用主题表面条，
扫描/调整目录在右侧；窄屏换行。资源行按复选框与名称、描述、路径、状态/失败原因排列，
准备上传按钮位于右侧，窄屏置于行内容下方。

批量栏位于列表之后，显示数量、仅跟踪和忽略，完成盘点为栏末次要动作。
当前批量只支持跟踪/忽略；上传逐项进入 UIX-11，不提供全部上传。
操作规则及零选择状态遵循 UIX-10，字段层级在通用 UI 的本地技能章节维护。

### 4.5 设置

Codex 设置分组为“连接与认证 / 技能目录”，宽屏使用图 14 的左右分区，
窄屏将分组放到内容上方。摘要、编辑和结果复用分区；具体返回规则见 UIX-12。
设置页中文/英文由应用 locale 映射，协议枚举不变；其他尚未国际化的工作区保持原语言。
页面底部弱化显示构建版本。

| 适配项 | Codex 具体值或入口 |
| --- | --- |
| 新建连接标识建议 | `hosts/codex.py` 读取 hostname；不可读时使用 `primary`。 |
| 新建本地身份标签建议 | 当前系统用户名；不可读时使用 `current-user`。 |
| 应用配置文件 | `$CODEX_HOME/config.toml`，未设置时为 `~/.codex/config.toml`；用于 MCP 接入的最小配置修改。 |
| 安装目录建议 | `~/.agents/skills`。 |
| 已有技能目录候选 | 已存在的 `~/.agents/skills` 与 `$CODEX_HOME/skills`，后者默认 `~/.codex/skills`。 |
| 默认值读取 | `nacos_status.defaults`，供页面与对话共用。 |
| 目录上限 | 当前每组 16 项。 |
| 页面控件 | 目录使用可增删的行；“添加默认目录”按钮追加建议，“使用默认配置文件”恢复配置路径建议。 |
| 暂未适配 | 项目目录选择与文件选择器。 |

建议生成、保留已有值、主动清空、去重、标识稳定性和无副作用要求统一见
[通用默认值规则](../../specs/onboarding-spec.md#5-本机默认值与自定义)。
Codex 当前为单中心，已有连接标识只读；hostname 与系统用户名不作为服务端身份。
默认路径依据：[Codex Skill 目录](https://learn.chatgpt.com/docs/build-skills)与
[CODEX_HOME](https://learn.chatgpt.com/docs/config-file/config-advanced)。

连接摘要使用显示名称、命名空间、Nacos 地址、认证方式、操作标签与检查状态。
本地标识和 Codex 配置路径位于高级区；操作标签采用本地化文案。
“技能目录”只配置目录，盘点入口在“我的资源 → 本地技能”。
页面登录/Token、环境变量与独立管理认证遵循通用凭据规则，具体支持范围见
[Codex 凭据适配](credential-onboarding-spec.md)。SVG 72–74 展示本适配凭据表单和摘要。

### 4.6 待处理操作与 Agent 任务

当前 `status` 只提供未完成/未知操作，不支持完整历史分页，顶部入口命名“待处理操作”。
Agent 当前提供文本任务输入；多模态/结构化内容没有专用视图时展示受限说明与脱敏详情。
当前任务与待处理的查询能力见第 7 节，行为按 UIX-08/UIX-14 处理。

### 4.7 类型专属详情与更多菜单

| 类型 | Codex 详情分区 |
| --- | --- |
| 已接入 Skill | 文件、来源、更新变更。 |
| MCP | 概览 / 工具 / 连接。 |
| Agent | 概览 / 发起任务 / 当前任务。 |
| 我的资源 Skill | 维护者概览 / 版本与发布。 |

菜单动作来自 UIX-02；工具发现、绑定、加载、任务和调用状态遵循对应通用操作，
本文件仅映射到本版页面分区与工具。

### 4.8 浮层与步骤的具体形式

行内菜单宽约 240–280 px；确认弹窗建议宽 480–560 px，最大宽为容器宽减 32 px。
窄屏详情步骤使用单列子页。菜单锚定、关闭与焦点、确认和步骤转换遵循 UIX，
不为每个 SVG 场景建立独立产品页面。

## 5. 视觉规则与设计变量

表单文字左右内边距 12 CSS px；下拉末端预留 40 CSS px，箭头距外边缘至少 12 CSS px。
强制颜色模式恢复原生箭头。详情操作栏、分页栏、菜单、弹窗和目录行按此间距体系留白。

### 5.1 Codex 主题映射

Codex 主题适配负责将应用提供的字体与颜色映射到通用语义角色。
原生主题信号优先，缺失时使用下表；具体变量及通知以实际桥接验证为准，
不假设存在未公开变量。主题变更与流程独立的行为由通用 UI 第 11 节定义。

### 5.2 本适配的后备尺寸与颜色

| 项目 | Codex 后备值 |
| --- | --- |
| 字体 | 系统 sans-serif，不下载字体。 |
| 字阶/行高 | 标题 20/28，分区 16/24，正文/按钮 14/20，辅助 12/18；字重 400/600。 |
| 间距 | 4、8、12、16、24、32 px。 |
| 列表 | 标准行至少 76 px，内容增加自然增高；细分隔线，选中轻背景。 |

## 6. 组件与状态

工作区、资源行、详情、操作摘要、配置字段、反馈、版本列表和批量栏的共同状态由通用 UI
定义。Codex 对以下应用加载状态采用专属文案：

| 核心状态 | Codex 文案 |
| --- | --- |
| `pending_host_verification` | 已安装，待 Codex 加载确认。 |
| `pending_host_reload` | 连接配置已保存，待 Codex 刷新。 |

`configured_unverified`、`result_unknown`、`recovery_required`、`reviewed` 及操作完成
含义沿用通用 UI，不在此重定义。文件核验与应用加载证据分别维护。

## 7. 工具映射与已知缺口

| 页面行为 | 本版工具（统一 `nacos_` 前缀） | Codex 当前映射或限制 |
| --- | --- | --- |
| 启动/上下文 | `status` | 安装、任务与操作记录需按当前上下文过滤。 |
| 保存/诊断 | `configure`、`diagnose` | 诊断只读 Client，没有独立 Admin 写权限探测。 |
| 页面凭据 | `credentials_begin`、`credentials_save` | app-only 加密提交，见凭据适配。 |
| 发现 | `search` | cursor 分页；前端使用请求序号。 |
| 我的资源/版本 | `my_skills`、`skill_status` | 原生 Admin login 与 owner 核验。 |
| 安装/更新/卸载 | `install_plan`、`uninstall_plan`、`apply` | 无消费端完整版本列表或独立更新摘要工具。 |
| 服务接入 | `discover`、`connection_plan`、`apply`、`mcp_probe` | MCP 工具发现与 Codex 加载分别核验。 |
| 服务解除 | `disconnect_plan`、`apply` | MCP 配置刷新说明；Agent 任务取消另行处理。 |
| 本地技能 | `scan`、`select`、`onboarding` | 批量跟踪/忽略，上传单项处理。 |
| 上传 | `upload_preview`、`upload_plan`、`apply` | 传 contentHash；冲突使用结构化信息。 |
| 提交/发布 | `publish_plan`、`apply`、`skill_status` | submit 可能直接上线；版本及 scope 来自核心。 |
| Agent 任务 | `agent_send`、`agent_task` | 查询/取消依赖 taskHandle；任务历史能力以核心实际返回为准。 |
| 异常核对 | `inspect_operation`、`reconcile`、`recover` | 按通用恢复边界映射本地操作。 |

页面请求携带最新 `_context`；只读请求使用上下文、视图和请求序号，写入以
planId/operationId 跟踪。当前 stdio MCP 与状态锁串行执行，不能承诺多请求并发。
请求隔离、重试和计划校验规则统一由通用操作规范定义。

## 8. 实现组织与兼容约束

本适配按主题/组件、视图、请求状态和动作流程拆分，源码模块化后合并为包内 HTML；
运行无外部 CDN、字体或开发服务器。两个入口使用相同产物，UI 与工具随同一插件版本交付。
协议字段、状态 schema 及受管数据的升级遵循通用架构与分发规范。

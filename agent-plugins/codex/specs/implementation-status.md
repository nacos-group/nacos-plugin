# Codex 实现与验收记录

本文件保留 Codex 0.1.0 的实现、缺陷和分层验收事实，不维护独立 TODO 或版本排期。
功能优先级、未来范围和稳定工作项统一见[全局路线图](../../specs/roadmap.md)；
本文的 T/D/DISC/UI/FIX 编号用于关联证据，不能作为其他宿主通过的证明。
新增认证、使用前更新和创建/修改后的发布询问均为规划，当前代码能力尚未改变。

## 1. 当前交付事实

当前源码版本为 `0.1.0`，包含首期资源管理、按 UI spec 重构的工作台、macOS 页面凭据、
目录默认值、意图发现、免安装试用与 ask/auto/never 复用策略，以及可读的原生 MCP 名称。
T09 能力验证通过，基础功能经使用者自测可用。版本号更新不替代逐项验收：UI11 的首次连接
三步向导、UI08/T18 的完整内嵌验证以及 DISC08 的原桌面对话即时原生加载继续保留。
核心自动测试、浏览器交互检查与包检查分别记录；下列结论不代表所有客户端兼容。
T01 的正式维护者/发布负责人、源码提交/tag 关联和发布 CI 仍由发布流程处理。

| 项目 | 已完成验收 | 保留边界 |

- DISC04 区分 MCP 握手、原生工具加载与业务调用；返回原生服务名/加载指引，工作流核对工具目录，拒绝下游响应覆盖验证状态，见 TM32。
- DISC05 实现三种隐式发现安装偏好、成功使用后复用、优先原生交互式询问，显式管理独立；模型真实行为仍待矩阵验收。
- DISC06 实现 Skill 内容预览、资源绑定的 MCP/A2A 不安装调用及策略执行前检查；通用用例见 CD-28–33。

- **缺口/待验** DISC08 原桌面对话的原生 MCP 即时生效：stdio-only 桌面尚无插件可调用的控制入口，等待应用提供正式刷新接口或可连接的现有控制 socket。后续须在同一桌面进程、同一会话验证配置保存、刷新、工具目录更新与原生业务调用，不通过重启/替代会话验收；生成中轮次与下一轮分别记录。当前继续用有界 MCP 转调完成任务。详细条件见[发现适配 §3.1](capability-discovery-spec.md#31-原桌面对话即时生效todo-disc08)。

- DISC10 原生 MCP 名称使用资源名与短身份标识；兼容旧哈希名，在明确保存计划中迁移并保护用户修改、名称冲突与恢复。
- **缺口/待验** FIX01 区分 Skill 版本的读取统计时间变化与内容/生命周期变化：现有上传计划比较会将读取 ZIP 引起的版本 updateTime 变化判为冲突。保留内容、可见性和审核状态保护，补充自读及并发读取场景回归后再关闭；重新生成计划可继续，尚未修复误报本身。

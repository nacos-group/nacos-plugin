# Codex TODO 与排期

本文件记录 Codex 适配的阶段范围、待办和实施状态。[通用功能规范](../../specs/functional-spec.md)
描述跨应用的完整目标；[通用路线图](../../specs/TODO.md)不继承本适配的完成状态。
保留既有 T01–T34、D01–D12 编号，实现与验收状态分别记录。

## 1. 已确认的设计方向

- 本适配面向 Codex；通用资源契约覆盖 coding agent 与 personal agent。
- 首期以 Skill 完整闭环为核心，同时消费已有 MCP 和远端 Agent。
- 首期允许只接入一个 Nacos 中心，完成认证、namespace、操作范围及下游凭据配置。
- 页面化在目标 Codex 验证可行后纳入首期；不支持时如实延期，不阻塞核心工具闭环。
- 首次初始化中的本地 Skill 扫描、资源选择、上传/托管和结果记录是首期必做项；
  页面不可用时仍须通过对话向导完成，用户可跳过并在以后重新进入。
- 创建/修改后的上传提示（包括工作流提醒和 Hooks）先保留调研与设计，后续再决定是否
  实现为可选能力，不列入首期开发或验收；持续自动上传和自动发布不作为首期要求。
- 同时保留源码和可安装发布产物，个人、团队及外部用户均是分发对象。
- 2026-10-19 已确认先迁移和重构 README/spec，再推进 P0 验证与 P1 开发。此前“只更新 spec”是原设计阶段边界，已结束；不授权扫描/上传用户实际业务资源或对外发布。

## 2. 首期范围与阶段顺序

| 首期主线 | 必须完成的结果 |
| --- | --- |
| Skill 完整闭环 | 首次初始化扫描已有 Skill、选择上传/托管、上传草稿、提交/发布、发现、下载、安装、使用，以及本地到远端和远端到本地的显式更新。 |
| MCP 与 Agent 消费 | 搜索和详情、配置连接/调用参数与独立凭据、能力验证和一次受授权的真实使用；Agent 采用一个明确协议版本。 |
| 插件配置 | 一个 Nacos 中心、namespace、目标认证、消费/开发操作范围、凭据管理和连接诊断；模型保留未来扩展多中心的身份边界。 |
| 条件纳入的页面 | 在支持的 Codex 中提供已安装、我的资源、搜索及配置/本地盘点入口，范围只覆盖本期资源与动作。 |

Skill 的“完整闭环”同时覆盖生产与消费：上传草稿不等于发布，下载不等于加载，使用需要
宿主证据，更新需要处理本地/远端差异。首期通过显式操作完成这些环节，不要求后台守护进程。
MCP 和 Agent 的服务由外部提供并已登记到 Nacos；首期插件负责发现、配置与消费。

Prompt 和 AgentSpec、Agent/MCP 定义管理、Codex 对外服务化、多中心管理、更多宿主、
持续自动上传/同步及企业集中运维均不属于首期必需内容。详细设计保留这些完整目标。

排期采用依赖驱动的相对阶段，不承诺日期、人力或工期。先完成配置与权限基线，再完成
Skill 生产消费链及 MCP/Agent 消费链；页面可以并行验证。创建后提醒另行评估。

| 阶段 | 范围 | 前置条件 | 退出标准 |
| --- | --- | --- | --- |
| P0：首期契约验证 | Codex/Nacos 版本、认证、Skill 生命周期、MCP/Agent 调用、初始化扫描及可选页面能力。 | 本 spec 可评审。 | 核心接口有证据，可选能力标明支持或延期。 |
| P1：首个可用版本 | 上述四条主线，加上必要的来源、版本、冲突恢复、诊断与源码/包分发。 | 核心 P0 验证通过。 | Skill 完整闭环、MCP/Agent 真实消费、单中心接入均通过；页面按实证结果交付。 |
| P2：资源扩展与自动化 | Prompt、AgentSpec、多中心、持续同步/草稿自动上传、更多宿主及企业治理交付。 | P1 有稳定安装记录和兼容矩阵。 | 按能力独立验收，不以功能数量代替更新/冲突正确性。 |
| P3：Agent 服务化 | 独立网关、隔离执行、任务协议、注册心跳和运维。 | 执行宿主和协议映射经验证。 | 其他 Agent 能通过 Nacos 发现并调用本地 Agent 服务。 |

P1 的变更计划、摘要、冲突检测与恢复记录是基础正确性要求；P2 扩展持续自动运行。
P3 的协议研究可提前，但不作为 P1 发布阻塞条件。

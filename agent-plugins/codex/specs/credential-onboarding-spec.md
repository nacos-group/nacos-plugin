# 初始化与页面凭据设计

状态：dev.13 的引导、预填已经用户反馈可用，但实际 Codex 保存被页面内容安全策略阻止。
dev.14 改为页面加密、本地 MCP 传密文，不再要求页面访问本机 HTTP。核心/协议、禁网浏览器
与真实钥匙串验证分层记录；macOS 页面账号密码保存已获用户确认，钥匙串拒绝/重试与应用
跨重启闭环仍待验。Linux 当前仅支持无认证或环境变量，原生 Windows 由于 POSIX 文件锁
依赖不能启动。dev.15 增加本机默认目录、标签与可选自定义引导，见 UI17、TM28。

本设计补充[通用连接契约](../../specs/connection-governance-spec.md)与
[设置页规范](resource-center-ui-spec.md#45-设置)。环境变量保留为可选路径，
在具备受保护凭据通道和本机安全存储的环境中，推荐用户在页面填写。

## 1. 用户流程

1. 用户在本地 Codex 对话发起“初始化 Nacos AI Registry”。先发现并调用 `nacos_status`，
   确认本机 MCP 可用。未配置是正常状态；云端缺少本机工具时说明如何转到本地，不自动创建
   云端任务、不反复重装，也不把“读取到设置 Skill”当作本机工具可用。
2. 复用用户已经提供的连接信息，只询问缺项。依次确认 Nacos API 地址、命名空间和用途；
   显示名称可选，内部连接/身份标识由适配器处理，不要求新用户理解底层字段。
   通常只填一个地址，管理入口不同时才展开。再询问技能安装目录和已有技能目录是否需要
   自定义；选择“不需要”时读取 `nacos_status.defaults`，使用本机默认值并展示实际路径。
   已有配置优先提供“保留当前目录”，不替换既有标识或自定义值。默认目录不安全或不存在
   时按[设置页规范](resource-center-ui-spec.md#45-设置)提示；空扫描目录不阻塞连接初始化。
3. 询问认证方式：`无需认证`、`Nacos 用户名与密码`、`访问令牌`。不根据地址推测无认证，
   也不默认使用管理员。OAuth、其他认证插件不在本次扩展范围内。
4. 需要认证时，询问凭据提供方式：`在页面填写（推荐）`或`使用环境变量`。
   只有本机安全能力通过检查才推荐页面填写；不可用时解释原因并让用户选择环境变量或稍后
   继续，不能静默降级到明文文件，也不能代用户选择无认证。
5. 页面填写：打开**当前对话侧栏中的资源中心 → 设置 → 连接与认证**，预填用户已确认的
   地址、命名空间、用途、目录和认证选择，定位凭据字段。提示：“连接信息已填好，请在右侧填写
   用户名和密码，点击保存配置。请勿把密码发到聊天中。”Token 模式使用对应文案。
   模型不输入、不读取、不回显密码，不代用户点击这次凭据提交。
6. 用户保存后，页面显示已保存状态并清空秘密输入。对话只读取配置版本及凭据是否已配置；
   不把“已打开页面”视为保存完成。初始化已包含只读诊断授权时，确认新配置已保存后再调用
   `nacos_diagnose`；页面自行使用时保留独立的“检查连接”按钮，不因保存而自动发起请求。
7. 展示检查的实际结果。成功只表示当前身份能读取资源，不代表管理写权限或下游服务可用。
   随后可选本地技能盘点，扫描、上传、发布仍分别授权。

环境变量路径只收集变量名，说明变量必须对**插件进程**可见；不能把某个终端中 `export`
成功等同于 Codex 已读到。该路径适合已有部署配置、自动化和没有可用图形凭据入口的环境。

## 2. 设置页状态

复用现有独立设置子页、分组、返回来源及中英文文案。不增加主工作区标签，不把问答、表单、
连接成功三个阶段拼在同一页；页面始终显示当前步骤。

| 认证方式 | 提供方式 | 可见字段与行为 |
| --- | --- | --- |
| 无需认证 | 无 | 无凭据字段，也不生成凭据记录。 |
| 用户名与密码 | 页面填写 | 用户名、遮罩密码；明确“保存到本机安全凭据存储”。 |
| 访问令牌 | 页面填写 | 遮罩 Token；使用同一套保存、更新与清除状态。 |
| 用户名与密码 | 环境变量 | 用户名变量名、密码变量名；不显示直接输入框。 |
| 访问令牌 | 环境变量 | Token 变量名。 |

已有凭据只展示“已保存”及存储方式，不从后端读回秘密填充输入框。提供“更换凭据”和
“清除已保存凭据”；清除仅作用于这条连接，明确后续需要重新认证。修改名称、目录等普通
字段不要求重新填密码。更换账号时更新身份边界，不能沿用旧账号的权限缓存或计划。

取消、离开、切换认证/提供方式清空尚未提交的秘密；非敏感草稿可保留。不能把当前的
“输入已暂存”通用提示用于密码。提交中禁止重复保存，失败保留非敏感信息并提示重新填写
秘密；错误详情不得包含请求体。关闭重开页面、重开对话及应用重启后能使用已保存凭据，
凭据变更后立即使旧登录缓存失效，日常更新不要求重启 Codex。

单独管理连接沿用同样的认证/提供方式选择。默认共用一组输入只用于用户明确选择的同一
Nacos 连接；更改目标 URL 时不得自动将旧凭据发给新目标。下游 MCP/Agent 凭据保持独立，
本次设计不自动扩展到它们。

## 3. 对话与页面交接

- 扩展侧栏打开工具，使其可接受设置路由和**非敏感草稿**。无参数调用仍打开资源中心，
  与现有 thread 入口兼容；工具参数不允许密码、Token 或任意秘密字段。
- 草稿仅预填，打开页面不会修改已保存配置。已有未保存编辑时不能被新工具结果静默覆盖；
  提示采用新草稿或继续原编辑。保存前复核当前连接上下文，拒绝覆盖其他窗口的新配置。
- 接收页面初始化工具结果后切换到设置，不能仅在对话中输出“已打开设置”。侧栏能力不
  可用时说明实际失败，给出已有资源中心的设置入口；不能悄悄改成云端设置。
- 页面向对话回传的状态仅包含已保存/待输入/失败、非敏感连接摘要与配置修订标识；
  等待用户完成保存或主动继续后读取状态，不以固定等待时长推断用户已经保存。

## 4. 凭据边界与落地条件

普通 profile、状态文件、操作历史、CLI JSON、工具结果及导出内容只保存不透明引用和状态。
用户名与密码组合或 Token 由本机凭据适配器保存；macOS 使用系统 Keychain，其他系统
须使用已验证的系统凭据服务。未验证的平台不宣称支持直接填写，不退回工作区明文文件。
不同连接、Client/Admin 用途及账号的引用必须绑定目标并校验归属，不能接受任意引用读取
其他连接的秘密。替换、清除及配置保存失败需要有一致性处理，不能留下“配置成功、凭据缺失”。

页面不向 `ui/message`、模型上下文、浏览器持久缓存、分析事件或诊断日志发送凭据明文。
仅设置密码遮罩或 `visibility: ["app"]` 不足以保证秘密不被记录。dev.13 的直接回环 HTTP
通道被 Codex 内容安全策略拒绝；dev.14 移除该服务和网络依赖，不要求用户放宽客户端策略。

- 页面通过 app-only `nacos_credentials_begin` 申请临时公钥。普通结果只有就绪状态，
  公钥、一次性会话标识、有效期放在 `_meta`，没有密码。每次保存新建 RSA 2048 密钥；
  私钥只保留在本机 SecKey 内存对象中，不导出、不持久化。有效期 60 秒，最多 32 个待用。
- 页面以 WebCrypto 生成随机内容密钥和 IV，使用标准 JWE Compact
  `RSA-OAEP-256` / `A256CBC-HS512` 加密 `{profile, changes}`。固定算法、不协商降级、
  不接受外部密钥 URL；RSA 包装密钥，AES-CBC 加密，HMAC-SHA512 认证，按标准截取标签。
- app-only `nacos_credentials_save` 仅接收密文信封和配置上下文。MCP/平台调用记录可能
  保存密文，不能宣传“没有任何凭据相关数据经过 MCP”。私钥留在本机，页面及本机插件才
  处理明文；用户确认的 Nacos 登录目标仍会收到登录凭据。
- 本机先检查格式、长度、固定算法、会话时效与上下文，RSA 解包后先验证认证标签再解密；
  信封最大 46,000 字符、明文最大 32 KiB。会话单次消费，包括失败尝试，完成或到期释放
  私钥；配置变更竞争由保存事务再次拒绝。异常只返回固定错误，不回显输入或原始错误。
- 页面没有 `fetch` 凭据通道，不声明本机 `connectDomains`。浏览器不支持 WebCrypto、
  旧工具版本、公钥异常时停止提交，不降级到明文 MCP 或聊天补交。
- Python 通过 Security.framework 的 SecItem API 保存不参与同步的 Keychain 条目；
  系统可能询问 Python 的钥匙串访问权限。条目按插件状态目录、连接身份、目标地址及用途
  隔离；配置仅含随机引用。读取失败由诊断反馈，不能以引用存在保证钥匙串一定可读取。
- 替换先建立新条目再原子保存引用，失败检查持久状态后回滚；遗留引用登记后重试清理。
  清理被系统拒绝时显示“旧凭据尚未清除”，不能声称已完全删除。
- 保存失败或结果未知后清空秘密，可选择“放弃草稿并重新读取”核对已保存状态；
  取消、离开与切换认证也清空秘密。页面不使用 localStorage/sessionStorage 保存它们。

禁网浏览器、WebCrypto 与 macOS 原生解密互通验证不替代目标 Codex 的内嵌工具与系统授权验收。

本机保存不代表密码永不离开机器：登录时仍需提交给用户确认的 Nacos 服务；正常部署
使用 HTTPS，禁止向重定向后的其他来源携带秘密。这里承诺的是不进入普通对话、发布包、
仓库或插件的普通配置/日志，不把页面隐藏字段解释成平台的完整隐私保证。

加密格式遵循 [RFC 7516](https://www.rfc-editor.org/rfc/rfc7516.html) 与
[RFC 7518](https://www.rfc-editor.org/rfc/rfc7518.html)，测试使用其公开验证向量并与独立实现互通。

核验依据：[MCP Apps 工具可见性](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx#visibility)、
[OpenAI 结构化设置](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#structured-settings)。
后者提供普通设置及工具入口，规范未声明通用密码保险箱；不能将普通字符串设置当作安全存储。

## 5. 验收范围

TM24–TM27 覆盖问答缺项、侧栏草稿、页面登录/Token、已有环境变量兼容、替换/清除、
上下文竞争、错误脱敏及跨进程使用。页面 UI、受保护通道与凭据服务必须一起验收；
纯前端样例或 mock 凭据服务通过不能替代目标 Codex + 系统凭据存储的结果。
真实地址、凭据、运行轨迹与平台验证脚本继续只保存在仓库外。
